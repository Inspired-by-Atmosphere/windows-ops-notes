# 校园网档案模板（把认证方式 / 带宽实测 / 纪律写成可复用素材）

> **适用平台**：任意校园网或单位专线环境（本文件是**空模板**，不含任何真实数据）  
> **一句话**：把「官方事实 / 接入拓扑 / 实测带宽 / 限制与纪律」四块固定下来，换环境时直接照表填，别每次重新摸。  
> **标签**：campus-network, template, documentation, speedtest

本笔记自包含，阅读顺序：**现象 / 触发场景 → 根因 → 命令与步骤 → 验证方式 → 坑位**。

---

## 现象 / 触发场景

- 换了驻地（宿舍 / 办公室 / 新校区），"网慢"的老结论不再成立，需要重新建立基线。
- 要判断"慢"是套餐档位、设备链路、互联 peering，还是代理线路（见 `network-speed-diagnostics.md`）。
- 有新设备要接入（路由器 / 小主机 / 多设备），需要先弄清认证方式与账号规则，避免把已有设备挤下线。

## 根因（为什么值得先建档）

同一句"网慢"，在不同环境下根因完全不同。把事实先写下来，后面每一次诊断都从"已知基线"开始，而不是从零重新测——省掉最多的不是测速时间，而是**误判后的返工**。

## 档案模板（复制下面四块，逐条填）

### 1. 官方事实（从网络中心 / 信息办的公开页面抄）

| 字段 | 值 |
|---|---|
| 出口带宽与出口数量 | <总带宽> / <出口 1、出口 2 …> |
| 到桌面的接入方式 | <千兆到桌面 / 百兆到桌面 / 无线> |
| 认证方式 | <Web 实名认证 / 客户端 / 802.1X> |
| 账号形式 | <统一认证账号 / 运营商宽带账号> |
| 运营商绑定规则 | <是否需在认证系统里绑定运营商账号才能走该出口> |
| 特殊终端申请路径 | <免认证内网 IP / 多设备协商 等，只写渠道不写具体联系方式> |

### 2. 接入拓扑（写成一行链路，别只写文字）

```
<终端> ──(有线/无线, 链路速率)──> <路由器/交换机> ──WAN──> <校园网出口> ──> <运营商/教育网>
```

- WAN 侧认证由谁完成：<路由器 / 每台终端各自认证>
- 是否做 MAC 克隆 / 绑定：<是 / 否；只记"是否需要"，不记录真实 MAC>
- 默认路由实际走向：<直连 / TUN 代理接管；若被 TUN 接管，规则怎么分流>
- ⚠️ 纪律条款：<例如"不要用个人账号直连 WiFi，会把已有设备挤下线">

### 3. 实测带宽（同一时段、多目标、多轮次）

| 目标类型 | 示例目标 | 速率 | 含义 |
|---|---|---|---|
| 国内高带宽镜像 | 高校开源镜像站 | ______ | 近似线路上限 |
| 另一个互联方向 | 不同运营商 / 教育网目标 | ______ | 互联 peering 是否拥堵 |
| 公共 CDN | 常见软件分发包 | ______ | 日常下载体验 |
| 境外（走代理） | 任意境外目标 | ______ | 代理链路是否瓶颈 |

测法见 `network-speed-diagnostics.md`（要点：Windows 原生 curl 不要写 `/dev/null`，要写真实临时文件，否则速度读数 0 是假象）。

### 4. 结论与提速顺序

把 lever 按收益降序写清楚，例如：

1. 换代理节点 / 线路（若境外占比高）
2. 套餐升档（若国内镜像已到顶，且不换设备即可支持）
3. 无线频段选择（5G 优先）
4. 走定向出口（校内资源走教育网出口等）

## 验证方式

- 填完档案后，用**同一组目标、同一时段**复测一次，两次结果同量级 → 基线可信。
- 做任何变更（换路由器、换频段、升级套餐）后只复测受影响的那一层，其余层结论沿用。
- 拿不准"是不是瓶颈"时，先看链路协商速率：`Get-NetAdapter | Select-Object Name, LinkSpeed, Status`。

## 坑位

- **别把"官方总带宽"当成自己的可用带宽**：总出口带宽是全校之和，与单用户档位无关。
- **别用单个目标的一次测速下结论**：镜像站限速、CDN 调度、peering 拥堵都会污染结果，至少跨 3 类目标。
- **别在公开仓库里放真实数据**：账号、MAC、公网 IP、楼栋与电话全部抹掉，只留结构性结论。
- **记录"实测时间 + 出口"**：同一环境早中晚差异可能大于换设备带来的差异，不记时间等于没测。
